- 設定頁及播放頁新增「我在高雄」。已發現的 PHILIPS TV 在本機裝置記錄中標記 `location=kaohsiung`；未將家用 IP、MAC 或 UUID 寫入程式碼。
- 未勾選時不列出高雄電視，後端也拒絕舊頁面對它發起新投放。既有會話仍可還原與控制，其他電視不受影響。
- 重掃、IP 變更與離線均保留地點及 MAC。DLNA 錯誤文字不再誤標為 LG。
- 使用者明確同意開啟區网投放並重啟。未修改防火牆、路由器、工作排程或依賴；服務已更新為背景執行，高雄勾選保持開啟。
- 使用者回報網頁不能控制後，查到電視仍在播放，但服務重啟後 `/api/cast/session` 為 null。新增本機會話保存，網頁重新連線時，精確核對會話標記及電視目前媒體 URI 後才恢復控制；保留原進度與暫停狀態，不呼叫重新播放或跳轉。
- 已停止、被其他內容取代、標記不符的媒體不能重新取得控制權。停止或取消時清除保存紀錄，舊工作執行緒不能復活已取代的會話。

## 已通過

- 投放相關測試 65 項（`test_cast*.py`）：既有 Chromecast、LG/DLNA、控制確認、取消、連播、裝置記錄，加上高雄篩選 5 項和重新連線 7 項。
- `test_playback_repairs.py`：17 項；`test_startup.py`：1 項。共 83 項相關測試，未擴大到全部片源測試。
- 重新連線測試包含真正的會話工作執行緒，驗證還原後可跳轉、續播、暫停，且不重新載入影片；電視本身以測試替身提供回應。
- `web` 的 `npm.cmd run build`：TypeScript 和 production build 通過，保留既有 bundle 大小提示。`git diff --check` 通過。
- 實際 API 高雄開關測試：關閉時隱藏 Philips、開啟後恢復，重啟後地點設定保存。
- Philips 實機：Gimy《蘭香如故》第 1 集播放並確認秒數前進，使用者確認畫面與聲音正常。
- 實機暫停於 48 秒，暫停中跳至 60 秒且保持暫停，續播、手動換至第 2 集成功。
- 第 2 集跳到片尾後，伺服器自動接第 3 集並確認播放；最後關閉測試連播並停止，電視回報 idle。
- 更新後本機健康檢查通過，區网投放與高雄設定持續啟用。

- 重新連線修正上線時 Philips 掃描為離線；服務重啟後的實機控制及使用者拖曳網頁進度條仍待電視恢復連線再驗證。
- 瀏覽器自動畫面操作受工具管理政策檢查阻擋，未繞過；不能把前端建置或 API 測試當成已完成點選驗證。

## 待機喚醒排查（2026-09-28）

- 使用者確認電視是遙控器關機待機，電源仍插著。實際喚醒會話等待後回報逾時，未播放影片。
- 額外從正在使用的區網介面，向子網廣播及一般廣播的 UDP 7/9 埠各送出三輪標準 magic packet；仍未看到 DLNA、Philips 遠端控制或 Cast 服務恢復。這只能證明已送出封包，不能證明電視收到。
- 待機時 ARP 查詢無回應；此現象與待機網路不可用相符，不能據此斷言機型絕對不支援網路喚醒。

- 將按鈕改為「嘗試喚醒並投放」，說明記住 MAC 並不保證支援喚醒，失敗時先用遙控器開機再掃描。
- 未修改電視電源設定、防火牆或路由器。使用者決定停止喚醒排查，改用遙控器手動開機。
- 此 Philips 的本機裝置記錄設為 `manual_power_on=true`，重新掃描後仍保留。介面改顯示手動開機提示，隱藏這台的喚醒按鈕及 MAC 喚醒設定；後端也拒絕舊頁面發出的喚醒請求，其他電視不受影響。
